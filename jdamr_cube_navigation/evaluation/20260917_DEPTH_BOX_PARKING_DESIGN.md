# Depth 박스 정밀주차 설계

## 결론

현재 Depth 카메라와 G4 라이다만으로 차체와 박스 사이 5cm를 마지막 순간까지 직접
관측할 수는 없다. 카메라 렌즈면은 차체 앞면과 같은 평면이고 Depth 검출기의 소프트웨어
하한은 0.35m다. G4 라이다는 차체 앞면에서 0.075m 뒤에 있으며 현재 `/scan`이 보고한
`range_min`은 0.28m다.

라이다가 유효한 최소 거리에서 차체 앞면과 장애물 사이 거리는 다음과 같다.

```text
라이다 기준 최소 거리 - 라이다의 후방 장착 거리
= 0.28m - 0.075m
= 0.205m
```

따라서 0.05m 목표까지 라이다가 직접 관측하지 못하는 거리는 다음과 같다.

```text
라이다가 관측 가능한 차체 최소 간격 - 목표 간격
= 0.205m - 0.05m
= 0.155m
```

Depth와 라이다가 모두 유효한 구간에서는 센서 기반 폐루프 접근이 가능하지만, 마지막
0.155m는 wheel odometry만으로 이동해야 한다. 이는 실험 후보로는 가능해도 미끄럼과
정지 지연을 외부 센서로 확인할 수 없으므로 5cm 정밀주차의 안정적인 최종안으로
간주하지 않는다. 수치의 출처와 유효 범위는
`evaluation/depth_box_parking_provenance.yaml`에 분리했다.

## 확인된 관측과 방향 부호

박스 전면 평면은 정지 상태에서 거리 0.762m, 우측 편차 약 0.0224m, 평면 각도 약
-1.05°, 신뢰도 약 0.97로 연속 `stable=true`를 유지했다. 박스를 오른쪽으로 옮긴 뒤
우측 편차 0.1284m에서 `angular.z=-0.05rad/s`를 2초간 발행한 시험에서는 편차가
0.0391m로 줄었다. 따라서 카메라의 양의 X, 즉 화면 오른쪽에 목표가 있을 때 ROS
각속도는 음수인 우회전 명령을 사용한다.

이 시험에서 평면 각도는 -2.34°에서 +3.63°로 변했다. 차동구동 로봇은 제자리 회전만으로
횡방향 위치와 최종 방향을 동시에 맞출 수 없다는 것을 실측으로 확인했다. 최종 접근은
곡선 이동으로 중심선에 들어간 뒤 평면 법선과 자세를 맞춰야 한다.

## 상대 목표 자세

Depth 전면 검출은 카메라 optical frame의 박스 중심 `(x, z)`와 카메라를 향하는 평면
법선 `(n_x, n_z)`를 제공한다. 목표 주차 자세는 박스 중심에서 법선 방향으로 원하는
이격거리만큼 떨어진 점이다.

```text
target_x = center_x + standoff * normal_x
target_z = center_z + standoff * normal_z
```

카메라 X축은 오른쪽이 양수이고 ROS `angular.z`는 좌회전이 양수이므로, 좌우 bearing의
부호를 ROS 각속도로 옮길 때 부호가 반대가 된다. 이 부호 관계는 위 실차 회전 시험으로
확인했다. 평면 각도와 좌우 bearing은 서로 다른 오차다. 하나의 제자리 회전으로 두 값을
동시에 0으로 만들지 않는다.

## 제어 상태기

1. `OBSERVE`: 8개 연속 프레임, 신뢰도 0.8 이상, 거리·좌우·각도 분산을 확인한다.
2. `ALIGN_BEARING`: 선속도 0으로 목표 중심을 향해 저속 회전한다.
3. `CURVED_APPROACH`: 선속도를 제한하고 bearing에 비례한 각속도로 중심선에 접근한다.
4. `ALIGN_NORMAL`: 저속에서 박스 평면 법선과 차체 전방 방향을 맞춘다.
5. `DEPTH_TO_LIDAR_HANDOFF`: 두 센서가 동시에 유효한 구간에서 거리 일치와 부호를
   확인한다.
6. `LIDAR_APPROACH`: 라이다가 유효한 차체 간격 약 0.205m까지 접근한다.
7. `FINAL_RANGE` 또는 `BLIND_ODOM`: 근거리 센서가 있으면 폐루프 접근을 계속한다.
   센서가 없으면 odometry 기반 제한 주행만 가능하며 정밀주차 완료로 확정하지 않는다.
8. `HOLD`: 0속도, 최종 간격, 방향과 유지 시간을 외부 기준으로 확인한다.
9. `ABORT`: 검출 불안정, 데이터 stale, 센서 불일치, 명령 소유권 충돌에서 즉시 0속도로
   전환한다.

## 5cm 목표의 구현 선택지

### 권장: 전면 근거리 센서 추가

차체 앞면에 짧은 거리용 ToF 또는 초음파 센서를 달아 마지막 0.155m를 직접 관측한다.
Depth는 물체 식별과 상대 자세, 라이다는 중거리 거리와 장애물, 근거리 센서는 최종 간격을
담당한다. 목표 간격 5cm를 반복 검증하려면 이 구성이 가장 명확하다. 센서 선정 후 실제
최소거리, 반사 재질, 시야각과 장착 오프셋을 별도 캘리브레이션해야 한다.

현재 우선 후보는 전방 중앙의 `VL53L4CD` ToF 브레이크아웃 1개다. 이 센서는 최종 거리만
담당하며 박스 식별이나 전체 접근 방향을 결정하지 않는다. 박스의 중심과 전면 법선은
Depth로 구하고, ToF는 차체가 가까워져 Depth와 G4가 유효 범위를 벗어나는 마지막 구간의
간격을 닫는다. 근거리에서도 좌우 각도를 독립적으로 확인해야 할 필요가 실측으로 확인되면
같은 센서를 좌우 2개로 확장한다. Depth 방향 추정이 안정적인 동안에는 1개로 시작한다.

### 확인된 연결 자원과 배선안

2026-09-17 Pi 4B에서 확인한 현재 연결은 다음과 같다.

| 인터페이스 | 현재 사용 | 추가 연결 판단 |
| --- | --- | --- |
| 헤더 UART `/dev/ttyS0` | 베이스 제어보드 | 다른 센서에 재사용하지 않는다. |
| USB `/dev/ttyUSB0`, `/dev/ydlidar_g4` | YDLIDAR G4 | 유지한다. |
| USB 2.0 | Orbbec Astra S | 유지한다. |
| USB 3.0 계통 | 감지된 장치 없음 | 추가 UVC 카메라나 USB 센서 후보이나 전력·대역폭을 별도 측정한다. |
| I2C `/dev/i2c-1` | 커널에서 활성화 확인 | ToF 연결 후보. 40핀 헤더의 물리 접근 방식은 조립 상태에서 확정한다. |

Pi 헤더에 직접 연결할 수 있는 Pi 호환 `VL53L4CD` 브레이크아웃의 기본 신호는
`SDA=GPIO2`(물리 핀 3), `SCL=GPIO3`(물리 핀 5), GND와 모듈 규격에 맞는 전원이다.
베어 센서가 아니라 전압 레귤레이터와 로직 레벨 변환이 명시된 브레이크아웃을 사용한다.
현재 Waveshare General Driver가 40핀 헤더에 장착돼 있으므로 센서선을 보드 아래에 끼우지
않는다. 제어보드의 노출 I2C 단자, 40핀 스태킹 헤더, 또는 USB-I2C 어댑터 중 실제 조립에
맞는 한 방법을 선택한다. 과거 I2C 버스를 끌어내린 불량 OLED 경로는 재사용하지 않는다.

ToF를 2개 사용할 때는 두 센서의 기본 I2C 주소가 같으므로 각 `XSHUT`을 서로 다른 GPIO에
연결해 부팅 시 순서대로 주소를 바꿔야 한다. 센서 1개에서는 `XSHUT`과 `INT`가 필수는
아니다. 모터나 고전류 장치를 Pi 헤더 전원에서 추가로 공급하지 않으며, 별도 전원을 쓸
때는 Pi와 공통 GND를 유지한다.

### 센서 전환 원칙

Depth를 목표물에 끝까지 밀착시키는 방식으로 사용하지 않는다. 센서 역할과 전환 조건은
다음과 같이 고정한다.

1. Nav2와 G4가 박스 근처의 대기 위치까지 이동한다.
2. Depth가 박스 전면인지 확인하고 중심·거리·법선을 이용해 차체를 정렬한다.
3. Depth와 G4가 동시에 유효한 중첩 구간에서 두 거리의 방향과 장착 오프셋을 확인한다.
4. G4 또는 Depth가 근거리 한계에 도달하기 전에 ToF 거리 제어로 넘긴다.
5. ToF가 목표 차체 간격 0.05m를 확인하면 정지하고, 명령 지연 뒤에도 간격이 유지되는지
   판정한다.

G4는 현재 9kHz 설정에서 `range_min=0.28m`다. 공식 사양상 4kHz 표본 모드에서는 최소
거리가 약 0.12m이므로, 차체 앞면보다 0.075m 뒤에 장착된 현재 구조에서 차체 간격 0.05m일
때의 라이다 거리 0.125m를 이론상 관측할 수 있다. 그러나 사양 경계보다 여유가 약 0.005m에
불과하므로 이를 반복 가능한 5cm 정차의 단독 근거로 사용하지 않는다. 먼저 4kHz 실측으로
근거리 반환율을 평가하되, 반복 오차와 누락이 크면 ToF를 최종 거리 센서로 사용한다.

### 하드웨어 추가 없음: 제한된 odometry 마감

라이다가 유효한 약 0.205m에서 정지한 뒤 odometry로 최대 0.155m를 매우 낮은 속도로
이동한다. 정지 지연, 바퀴 미끄럼과 물체 접촉을 직접 관측하지 못하므로 작업자 감시 아래
실험 후보로만 사용한다. 외부 줄자 또는 고정 카메라 ground truth 없이 5cm 달성을
주장하지 않는다.

### 목표 정의 변경

물리 간격 5cm가 아니라 안전한 이격거리에서 목표 pose 오차 5cm 이내를 성공 조건으로
둔다. 기존 Gazebo 주차의 `xy_tolerance_m=0.05`는 이 정의이며, 박스와 차체 사이를 5cm로
만드는 목표와는 다르다.

## 다음 구현 게이트

- Depth 최소 유효거리를 0.35m로 가정하지 않고 실제 박스 재질에서 접근별 유효 픽셀률을
  측정한다.
- 라이다와 Depth가 동시에 박스를 보는 구간에서 거리 차이와 시간 오프셋을 기록한다.
- 근거리 센서가 없으면 최종 상태 이름을 `BLIND_ODOM_EXPERIMENT`로 유지하고
  `PARKED_5CM`을 발행하지 않는다.
- 실제 5cm 성공 판정은 외부 줄자·기준판 또는 독립 ground truth로 확인한다.
- 실차 구동 서비스는 현재 중지 상태이며 이 문서 작성 과정에서는 이동 명령을 발행하지
  않았다.
