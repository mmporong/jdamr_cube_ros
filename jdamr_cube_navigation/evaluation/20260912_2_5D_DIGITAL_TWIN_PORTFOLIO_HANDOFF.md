커밋·push, 프리뷰 배포 확인까지 수행하되 프로덕션 기본 브랜치에는 사용자의 명시적 요청

## 공개 본문 초안

실차 주행 중 박스가 기준 경로를 막자 로봇이 선회했고, 사람과 박스가 함께 나타난 구간에서는
긴급정지 후 같은 목표로 주행을 재개했습니다. 이 장면을 영상 설명으로 끝내지 않고 다시
실행할 수 있는 검증 환경으로 옮겼습니다.

2D LiDAR로 만든 점유격자에서 벽과 통로를 추출해 Gazebo 충돌 메시로 변환했습니다. 실차
경로, Keepout 마스크, 박스 위치와 사람 횡단 장면도 같은 좌표계에 배치했습니다. 2D LiDAR와
Nav2를 그대로 사용해 경로계획, 선회, 긴급정지, 재개를 다시 실행했고 20개 경유점과 세 개의
장애물 장면을 모두 완료했습니다.

지도 전체를 보여주는 화면은 벽에 차량이 가려지는 문제가 있었습니다. 충돌 판정에는 2.4 m
벽을 유지하고, 화면에는 0.65 m 높이의 절개형 벽을 따로 사용했습니다. 후상방 추적 카메라를
추가해 전체 지도에서의 위치와 차량 주변의 장애물을 한 화면에서 확인할 수 있게 했습니다.

저마찰 상황은 실차 마찰계수를 복제한 결과가 아닙니다. 마찰 이상이 감지됐다고 가정한 합성
스트레스 구간이며, 보호정지, 재위치화, 제한속도 재개, 복구로 이어지는 상태 전이를 검증하는
데 사용했습니다.

## 이 결과를 디지털 트윈이라고 부를 수 있는 범위

권장 표현은 `실차 데이터 기반 2.5D 주행 시나리오 재현형 디지털 트윈`이다.

- 실제 입력: 2D LiDAR 점유격자, 저장 지도 좌표계, 경유점 경로, Keepout 마스크, 실차 영상에서 확인한 장애물 장면
- 시뮬레이션 변환: 점유 셀을 3D 벽 충돌 메시로 확장하고 박스·사람 모델을 같은 지도 좌표계에 배치
- 실행 대상: 2D LiDAR, Nav2, Collision Monitor, 마찰 이상 복구 상태기계
- 확인한 동작: 고정 장애물 선회 2건, 사람 등장 긴급정지·동일 목표 재개 1건, 저마찰 복구 1회

엄격한 실시간 디지털 트윈으로 표현하지 않는다. 실물과 시뮬레이터의 양방향 실시간 동기화,
사진측량형 3D 복원, 벽·가구·장애물의 실측 치수 복제, 실차 마찰계수 재현은 수행하지 않았다.

## 화면 구성 지시

1. AMR 사례 대표 미디어는 이 4배속 관제 영상으로 교체한다.
2. 영상 바로 아래에는 `실차 기록 → 2D 점유격자 → 3D 충돌 메시 → Nav2 재실행` 흐름을 한 줄로 배치한다.
3. 기존 지도 생성 설명과 내용이 겹치는 별도 미디어 블록은 합친다.
4. 정지·선회·재개가 보이는 장면을 먼저 노출하고 수치 표는 그 아래에 둔다.
5. 데스크톱에서는 좌우 카메라가 잘리지 않게 원본 비율을 유지한다.
6. 모바일에서는 영상 전체를 축소하고 임의로 세로 크롭하지 않는다.
7. 자동재생은 무음·반복으로 설정하고, `prefers-reduced-motion`에서는 poster와 재생 버튼을 제공한다.
