# 2026-09-29 출발 준비와 미완료 항목

## 확인된 실패

- AMCL은 초기 pose가 없었으나 coordinated manager가 planner 활성화를 진행했다. 11:04:18부터 global costmap이 TF를 기다렸고 11:05:18 활성화가 실패했다. 초기 pose 입력은 11:05:35로 늦었다.
- 두 이동 시도는 AMCL y 분산 0.01660/0.01693 m²가 서비스 후보 상한 0.010 m²를 넘어 취소됐다. 분산 상승의 근본 원인은 미확정이다. 같은 시간대 scan TF 과거 시각·queue-full 폐기 로그가 있다.
- 마지막 복구 시도는 주차 제어기 파라미터 조회 응답 대기에서 실패했다. 설정값 불일치가 확인된 것은 아니다.
- 부팅 뒤 Astra가 USB 목록에 보여도 드라이버 open이 실패했다. USB 장치 목록만으로 영상 수신을 승인할 수 없다. USB 재연결 후 depth image와 camera_info 수신을 확인했다.
- 테이블 도착·5 cm 주차·충전소 복귀는 이번 실행에서 미완료다. 파이 재부팅 이후 과거 위치를 현재 위치로 사용하지 않는다.

## 반영

- 지도 초기 스트림 대기와 실제 지도 identity 불일치를 구분한다. 파라미터 조회 대기는 5초이며, 응답 실패나 값 불일치 시 이동하지 않는다.
- 센서 목록의 첫 짧은 DDS 탐색에서 /scan이 빠졌으나 후속 실제 scan 수신이 확인됐다. 필수 토픽이 없으면 탐색을 한 번 더 수행하며 재조회에도 없으면 기존처럼 실패한다. 토픽 목록 발견을 데이터 품질 확인이나 주행 준비 완료로 취급하지 않는다.
- `restaurant_session.sh start --prepare-only`는 keepout/map/AMCL만 활성화하고 navigation manager는 대기시킨다. 초기 pose·이동 goal은 보내지 않는다.
- `python3 -m jdamr_cube_navigation.activate_navigation`은 현재 위치추정·TF·정지·배터리·지도 identity를 확인한 뒤 기존 navigation manager를 활성화한다. 초기 pose나 이동 goal을 만들지 않는다. 충전 중에는 실행하지 않았다. 활성화 이후 실패하면 RESET과 미활성 상태 확인을 수행하며 원복 응답이 불확정이면 출발 불가 이벤트를 기록한다.
- 기존 지도와 목적지 좌표는 보존하고 최신 departure_mask_v2 registry를 준비 세션에 사용한다. 새로운 지도는 별도 경로에 생성해야 하며 기존 충전소·테이블 좌표와 마스크를 자동 재사용하지 않는다.
- Astra 회복은 기본적으로 장치가 보이면 포트를 건드리지 않는다. 드라이버 open 실패가 확인된 경우 선택적 `ASTRA_USB_FORCE_RECOVERY=1`로 지정 카메라 포트만 재시도할 수 있다. USB 재연결이 필요했던 이번 사례를 자동 회복 성공으로 기록하지 않는다.

## AMCL 갱신 후보

- `update_min_d`: 0.25 m → 0.05 m, `update_min_a`: 0.2 rad → 0.05 rad.
- 이는 실측 캘리브레이션 값이 아니라 저속 주행에서 센서 보정 간격을 줄이는 소프트웨어 후보다. 0.08 m/s에서 거리 문턱 도달 간격은 3.125초에서 0.625초로 줄지만 실제 갱신 시각은 scan·TF 수신과 필터 상태에 달려 있다.
- 상한 0.010 m²·yaw 10°와 scan/odom 신선도·충돌·저전압 정지는 유지한다. 분산 수치를 임의로 낮추거나 기존 일반 복도의 큰 분산 상한을 정밀 주차에 복사하지 않는다.
- 근거: [Nav2 Jazzy AMCL 설정](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/others/configuring_amcl/)에서 위 두 항목은 필터 갱신에 필요한 이동·회전량이다. 갱신 간격 변경이 이번 분산 상승을 해결한다는 인과 관계나 실차 효과는 아직 검증하지 않았다.

## 출발 후 남은 검증

1. 케이블 분리·배치 후 현재 위치를 확인하고 AMCL을 초기화한다. 충전 위치를 주행 출발 위치로 간주하지 않는다.
2. 정지 상태 scan-지도 정합과 분산·TF 신선도를 확인한다. 안정되지 않으면 기존 원본을 보존한 채 필요한 주행 영역을 Cartographer로 다시 매핑한다.
3. 짧은 접근에서 scan/TF 폐기·AMCL 분산·CPU·배터리를 기록한다. 재생성 지도는 충전소·테이블 영역·마스크를 새 좌표계로 다시 등록한다.
4. 테이블 박스 면 정렬·5 cm 접근은 실차 실행과 외부 간격 확인 뒤 완료로 판단한다.
